# ADR-007：Visual Deck V4 chain-2 使用局部修订补丁

- 状态：已采纳
- 日期：2026-08-03
- 范围：`VISUAL_DECK_V4` 修订应用阶段

## 背景

V4.1 真实 12 页验收已完成五阶段规划、并发出图、逐页审查与套审，但在第四轮修订应用时
以 `REVISION_SCOPE_VIOLATION` 失败，未形成 PPTX。修订计划只命中 8 页的 9 项操作，旧合同却要求
文本模型重新返回完整 12 页 `VisualDeckV4ProposalDraft`，同时核心要求全局字段与所有非目标页面
逐字不变。模型对非目标内容的轻微改写会使整轮修订失败；再次要求完整回传并不能可靠消除这种
能力冲突。

问题不在图片生成、并发或账务。根因是 chain-2 的修订输出权限大于批准的修改范围，而核心只能
在接收完整 Proposal 后再发现越权。

## 决策

当前编译器 `visual-deck-v4-chain-2` 的修订应用改用严格局部补丁合同，模型只能返回：

- `contentPatches`：`UPDATE_CONTENT` 页允许修改的内容、来源和直接相关视觉字段；
- `layoutPatches`：`RELAYOUT` 页允许修改的视觉隐喻、构图、信息层级和跨页关系；
- `redrawOnlyPageNumbers`：现有施工单已表达修订意图、只需结合持久化 operation instruction 重绘的页。

纯 `REGENERATE_IMAGE` 页不进入文本模型输出。一个页面只能由一种补丁或 redraw-only disposition
拥有；同页同时包含内容与布局操作时，内容补丁优先并承载直接相关视觉修改。

核心按批准的 Revision Plan 确定性校验页归属并合并补丁。缺页、越权页、重复归属、错误补丁类型、
无实际变化、来源漂移或超出页码范围均在媒体提交前拒绝。全局字段、冻结角色、非目标页及补丁类型
未授权的字段直接从已持久化 Proposal 继承，不依赖模型重复抄写。

`sourceChunkIds` 是集合语义，单纯改变顺序不算实际修改。no-op 判定会先规范化该字段，防止模型用
来源顺序变化冒充内容修订。

redraw-only 是一个受限执行 disposition，不是“核心已经证明原 Brief 语义正确”。核心只能证明它命中
批准页面、保留来源谱系且没有改写规划；媒体编译必须把持久化 operation instruction 完整加入重绘
提示词，重绘页随后必须重新经过页审和套审，不能从 redraw-only 直接交付。若未来要求在付费重绘前
证明 Brief 已表达自然语言修订，需要引入可验证的外部语义判定合同，不能把模型自我声明当作证明。

## 兼容与恢复

- `visual-deck-v4-chain-1` 保持原完整 Draft 合同、Schema 名称和解析路径，保证在途任务可恢复；
- chain-2 使用新的内部 Schema 名称 `ppt_agent_v4_revision_application_patch_v1`；
- 合同修复最多使用现有第二个确定性 repair key；
- Provider 瞬态或不确定失败继续使用原幂等键，不切换合同、不重复提交；
- 所有 V4 修订路径（包括纯 `REGENERATE_IMAGE` 快速路径）先校验持久化 compiler 版本；
- 成功补丁仍经过现有 Proposal/Blueprint、来源谱系和 V4 修订范围验证；
- 公共 HTTP、OpenAPI、宿主接入和账务合同均不改变。

## 后果

优点：模型从源头无权回写整套 Proposal，局部返修不再因非目标页面的偶然改写而整体失败；核心可以
证明每个变化都来自批准操作，并保持重放与断点恢复的确定性。

代价：内部同时维护 chain-1 完整 Draft 与 chain-2 局部补丁两条兼容路径；模型需要明确选择实际补丁
或 redraw-only disposition，不能用无变化补丁假装完成。

## 拒绝方案

- 放宽非目标页逐字不变校验：会静默接受未审批内容变化，破坏来源和质量边界；
- 收到完整 Proposal 后丢弃越权字段：无法证明模型预期修改与最终应用一致，也会掩盖合同错误；
- 继续用更强提示词要求完整回传：真实验收已证明提示词不能稳定约束逐字复制；
- 只重试完整 Proposal：增加延迟和文本成本，仍可能重复触发同类漂移；
- 让宿主处理局部合并：会泄露内部编译器结构并破坏 PPT Agent 的独立边界。
