# 已审核逐页设计稿超时恢复实施计划

## 目标

修复 FrameFlow 已审核 `PPT_PAGE_DESIGN` 被降级为长文本、再次触发整套蓝图规划并在 180 秒超时的问题。保持现有确认和计费合同，复用 PPT Agent 已有的逐页幂等执行、持久化、审查与 PPTX 交付链路。

## 共同根因

1. 宿主成果合同丢失：FrameFlow 保存了结构化逐页设计稿，提交时只传 Markdown，Agent 无法识别“已审核”和页面边界。
2. 执行粒度错位：已确定的 12 页内容被重新塞入一个不可恢复的整套规划请求，相同大请求超时后原样重试三次。
3. 错误语义混层：流读取超时被归为 Provider 不可用，技术故障又被 UI 当作严重质量问题和 80% 进度。
4. 恢复动作断层：底层存在规划重试和事件恢复，聊天主卡没有把可重试动作、恢复范围和积分状态直接呈现给用户。

## 实施范围

1. 公共合同增加版本化 `APPROVED_PAGE_DESIGN` 来源，携带成果版本、内容哈希、课程元数据和有序 `pages[]`。
2. FrameFlow 从权威成果生成同一份报价与 Agent 输入，不再只发送渲染后的 Markdown。
3. PPT Agent 对审核稿执行确定性蓝图转换，跳过 `create_blueprint`；直接进入逐页执行，不再要求用户二次确认同一蓝图。
4. 每页只形成一个整页视觉生成单元，现有 Worker 每次最多提交一个；完成状态、缩略图和预算按页持久化。
5. 同时修正流读取超时分类、Bun SSE 空闲连接、失败文案、错误图标、真实页进度和聊天卡原位规划重试。
6. 发布后受控恢复指定 12 页失败任务，持续监控至 PPTX 可下载，并核对整单预留的最终释放/结算。

## 非目标

- 不在本轮重写完整 PPT Agent 架构。
- 不增加图片并发；第一阶段保持每次最多提交一页。
- 不把未知计费状态自动标记为未收费，也不使用新幂等键盲目重试。
- 不处理台账中与本次超时无直接关系的附件格式、全站下拉框和其他布局问题。

## 测试先行清单

1. 合同测试：审核稿页码连续、版本/hash 合法、字段有界，普通 TEXT/SOURCE_PACKAGE 行为不变。
2. 宿主测试：报价所用成果与 Agent 收到的 `pages[]`、version/hash 完全一致。
3. 规划测试：审核稿不调用模型，生成合法蓝图，直接转入 `EXECUTING`，每页只引用自身来源块。
4. 逐页测试：12 页产生 12 个稳定媒体键，单次 Tick 只提交一页，刷新和重启不重复提交已完成页。
5. 错误测试：请求建立和流读取超时均为 `PROVIDER_TIMEOUT`；普通断流仍为可重试的不可用错误。
6. UI 测试：失败不展示内部码、不称为质量问题、不显示绿色完成或虚假 80%，可重试规划在主卡直接可用。
7. 事件测试：SSE 有心跳，断线按游标恢复且不重复事件。
8. 计费测试：规划失败不产生页面结算；终态后释放整单剩余额度；已完成页只结算一次。

## 固定验收标准

- 指定 12 页审核稿在生产不产生 `create_blueprint` Provider 请求。
- 任务进入逐页生成后，每次最多新增一个媒体提交，完成页刷新/重启后不丢失、不重做。
- 用户在聊天主卡看到真实的“已完成页数/总页数”、可理解失败原因和适用的重试动作。
- 生产 Run 最终为 `COMPLETED`，预览和 PPTX 均可下载；积分流水满足“已完成页一次结算、未使用余额释放”。
- FrameFlow 与 PPT Agent 的测试、类型检查、构建通过；真实 Chrome 桌面与移动回归通过；三个独立审查智能体对整个大阶段无未解决 P0/P1。

## 回退

发布前分别备份 FrameFlow release、PPT Agent release、Agent SQLite、FrameFlow 数据库和环境配置。代码回退只切换两个 `current` 软链接并重启对应服务；数据回退仅在确认上线后没有新任务或计费副作用时执行，否则保留新库并以前向修复处理。
